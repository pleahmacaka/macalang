# Benchmarks

Representative recursion-heavy integer kernels, comparing **Maca** against C,
JavaScript (Node), and Python. Maca is built through the `maca` CLI
(Maca → C → `cc -O2`), so on compute-bound code it lands in C's ballpark —
that's the "C-tier native" claim — while staying far ahead of interpreted /
JIT'd runtimes on call-bound work.

## Kernels

| kernel | what it stresses | workload |
|---|---|---|
| `fib` | tree recursion, call overhead | `fib(40)` |
| `tak` | Takeuchi, dense nested recursion | `tak(32,16,8)` |
| `ackermann` | deep non-primitive recursion | `ackermann(3,10)` |

Each language computes the identical result (checked by the harness).

## Run

```sh
cargo build --release -p maca-driver     # the maca CLI
python3 bench/run.py --runs 5            # builds + times everything
```

Needs a native `cc` (Maca and C link through it here), plus `python3` and
`node` for those columns. Results land in `results.md` and `results.json`.

## Layout

- `*.maca` — the Maca implementations (also compile+run under `maca run`)
- `ref/*.c`, `ref/*.py`, `ref/*.js` — the reference implementations
- `run.py` — build + time + verify + write the table
- `results.md`, `results.json` — latest results (regenerated by `run.py`)

Times are median wall-clock of the compiled/loaded program (compiled languages
are built once, then timed); they depend on the host, so re-run locally for
numbers you can cite.
