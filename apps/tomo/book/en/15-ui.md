# Interfaces and Documents

Maca has a syntax for HTML elements and a stylesheet generator that reads the
classes you write. Both are part of the language, not a library. The same markup
becomes a live DOM in the browser and a string of HTML in a native binary. This
page was produced by it.

## An element is a call

Any HTML tag name can be called:

```maca
article(class="prose",
    h1("Hello")
    span("Some text"))
```

Named arguments are attributes; positional arguments are children, separated by
commas or by nothing at all. An element is an ordinary expression:

```maca
item(name: str) -> str => li(name)

list_of(names: str[]) -> str =>
    ul(names.map(item).join(""))
```

## Two targets, one syntax

```
maca build app.maca --target js -o out
```

builds a reactive page: elements become `createElement` calls, `onclick=`
attaches a handler, and `value=` on a state name binds it two ways. The names
are the platform's own.

```maca
count = 0

bump() { count = count + 1 }

main() -> Element =>
    div(
        button(onclick=bump, "+")
        span("{count}")
    )
```

There is no repaint call. **Assigning a declared name is the update**: the nodes
that read `count` run again. A handler that assigns three names repaints once,
when it returns.

```
maca build gen.maca -o gen
```

builds a native binary, and there the same elements render to **text**:

```maca
main() -> int {
    info(article(class="prose", h1("Hi") span("Body")))
    0
}
```

```
<article class="prose"><h1>Hi</h1><span>Body</span></article>
```

An event handler has nowhere to attach in a string, so `on:click=` on the native
target is a compile error naming `--target js`. A vanilla `onclick="…"` is an
ordinary HTML attribute there.

## A definition wins over a tag

`label`, `code`, `main`, `section`, `p`, `a`, `form` and `option` are HTML tags
*and* names people give their own functions. The definition wins:

```maca
label(pos: bool) -> str => pos ? "right" : "left"

main() -> int {
    info(label(true))     // "right": your function, not <label>
    info(span("tag"))     // "<span>tag</span>": nothing shadows `span`
    0
}
```

This is the ordinary scoping rule, applied before the tag is considered.

## A view can contribute a list of elements

A child may be a **list** of elements, each a child in its place:

```maca
Link = { title: str, icon: str }

pencil(on: bool) -> Element[] {
    if !on {
        return []
    }

    [button(class="pencil", "edit")]
}

row(link: Link, on: bool) -> Element =>
    li(class="row",
       [i(class="icon", link.icon), span(class="title", link.title)]
           ++ pencil(on))
```

`Element` is a rendered element and `Element[]` a list of them. `[]` contributes
**nothing at all**: no node on the JS target, no markup on the native one, so a
view with nothing to show returns the empty list rather than an element carrying
`class="hidden"`.

```maca
ul(links.map(l => row(l, editing)))
```

`-> Element` or `-> Element[]` tells the compiler this call hands back nodes
rather than text. A function returning `str` is still a child rendered as
text.

## Styles are generated, not linked

Classes use Tailwind's utility names, and the compiler generates the stylesheet
for the utilities your program mentions. `styles()` returns it as a string:

```maca
page() -> str =>
    div(class="max-w-2xl mx-auto font-bold", "text")
```

```css
.font-bold { font-weight:700; }
.max-w-2xl { max-width:42rem; }
.mx-auto { margin-left:auto;margin-right:auto; }
```

One rule per utility written, and no network fetch.

## Write one

A page, complete, with no other files:

```maca
main() -> int {
    write_file("index.html",
        "<!doctype html>\n"
        ++ html(lang="en",
            head(
                meta(charset="utf-8")
                meta(name="viewport", content="width=device-width,initial-scale=1")
                title("Notes")
                style(styles()))
            body(class="font-serif bg-white dark:bg-zinc-900",
                element("main",
                    h1(class="text-[2rem] font-bold", "Notes")
                    span(class="my-4", "Written in Maca.")))))
    0
}
```

## Where the full answer is

[The UI Syntax](a11-ui.md) has the sharp edges: hyphenated attributes, boolean
attributes that control an attribute's *presence*, `element(tag, …)` for a tag
chosen at run time, the variant tables, arbitrary values in brackets, and the one
place classes are **not** collected: inside a raw `"""…"""` string.
