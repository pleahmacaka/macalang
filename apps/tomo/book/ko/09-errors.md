# 오류

Maca에는 잡을 예외도, 벗겨낼 `Result`도, 확인할 `null`도 없습니다. 실패할 수
있는 함수는 실패함으로써 그렇다고 말하고, 호출자가 그것이 무엇을 뜻하는지 셋 중
하나로 정합니다.

## 실패하기

`fail`은 메시지를 받고 스택을 되감습니다.

```maca
divide(a: int, b: int) -> int =>
    b == 0 ? fail "division by zero" : a / b
```

반환 타입을 보세요. `int`를 감싼 무언가가 아니라 그냥 `int`입니다. 실패는 값의
일부가 아니므로, 실패가 일어난 곳과 처리되는 곳 사이의 모든 시그니처를 통과하며
꿰어질 필요가 없습니다. 다른 언어에서 예외가 존재하는 이유와 같되, 예외 클래스
계층을 설계할 필요는 없습니다.

## 그냥 두기

평범하게 호출하면 실패가 프로그램 밖으로 곧장 빠져나갑니다.

```maca
main() -> int {
    info("{divide(10, 0)}")
    0
}
```

는 표준 에러에 `error: division by zero`를 찍고 상태 1로 종료합니다. 명령행
도구라면 대개 이게 정확히 맞습니다. 메시지는 사용자에게, 종료 코드는 셸에
닿는데, 그걸 위해 쓴 코드는 없습니다.

## 넘기기

붙여 쓴 `?`는 실패를 *여러분의* 호출자에게 전파합니다.

```maca
checked(n: int) -> int {
    v = divide(84, n)?
    v + 1
}
```

`divide`가 실패하면 `checked`도 같은 메시지로 실패하고 `v + 1`은 실행되지
않습니다. `?`는 앞에 공백 없이 붙여 씁니다. 포맷 스펙과 삼항을 가르는 것과 같은
붙여쓰기/띄어쓰기 규칙입니다.

## 처리하기

`try`는 식을 실행하고, 되감는 대신 실패를 여러분 손에 쥐여 줍니다.

```maca
msg = try divide(10, 0)
```

`msg`는 실패의 메시지이고, 아무것도 실패하지 않았으면 **빈 문자열**입니다.
그래서 에러 처리의 모양은 길이 검사입니다.

```maca
main() -> int {
    msg = try risky_thing()
    msg.length() > 0 ? report(msg) : 0
}
```

한계를 분명히 짚고 갑니다. 진짜 한계니까요. `try`는 *메시지*를 줄 뿐 값을 주지
않습니다. `try divide(10, 2)`는 `5`가 아니라 빈 문자열입니다. 결과와 국소적인
실패 처리가 둘 다 필요하다면, 연산을 실행하고 따로 확인하거나, 그 함수는
`fail` 대신 합타입을 반환하게 하세요.

## 무엇을 쓸까

대부분의 코드는 `?`를 쓰거나 아무것도 쓰지 않아야 합니다. 전파가 기본인 이유는,
실패에 대해 *무언가 할 수 있는* 곳이 그것을 알아챈 곳인 경우가 거의 없기
때문입니다. 그리고 명령행 프로그램의 꼭대기까지 올라가게 두면 쓸 만한 에러
메시지가 공짜로 나옵니다.

`try`는 진짜로 대안이 있는 경계에 아껴 쓰세요. 재시도, 기본값, 다시 시도할
사용자에게 보낼 메시지 같은 것들이요.

그리고 실패가 예외적인 결과가 아니라 평범한 결과라면 — 맞지 않을 수도 있는 파싱,
없을 수도 있는 조회 — `fail`을 아예 쓰지 마세요. 합타입(6장)이 타입에 그렇게
적어 두고, 그러면 컴파일러가 모든 호출자에게 그것을 처리하게 만듭니다.

```maca
Parsed = Found(int) | Missing(str)
```

새겨둘 구분은 이것입니다. `fail`은 계획하지 않은 경우를 위한 것이고, 합타입은
계획한 경우를 위한 것입니다.
