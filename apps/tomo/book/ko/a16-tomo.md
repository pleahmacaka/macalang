# Tomo: 지금 읽고 있는 이 책

이 핸드북은 마크다운 파일들이 든 디렉터리입니다. 지금 읽고 있는 HTML은
Maca로 쓴 정적 사이트 생성기 `apps/tomo/tomo.maca`가 만들어냈습니다.
여기 있는 이유는 이 책의 거의 모든 것을 한꺼번에 쓰기 때문이고, 자기 문서를
만드는 도구가 언어에 대한 정직한 시험이기 때문입니다.

*Tomo*는 스페인어로 책의 한 권을 뜻합니다. *maca*와 같은 안데스의 결입니다.

## 무엇인가

대략 mdBook입니다. 마크다운이 들어가고 탐색 가능한 HTML 책이 나옵니다. 다만
의도된 차이가 하나 있습니다. **i18n이 플러그인이 아닙니다.** 데이터 모델
자체입니다.

## 설정

```toml
[book]
title = "The Maca Handbook"
languages = ["en", "ko"]
chapters = [
    "## Learning Maca|Maca 배우기",
    "# Getting Started|시작하기",
    "00-introduction",
    "01-installing",
]
```

`languages`는 리스트이고 첫 항목이 기본값입니다. 챕터는 한 번만 이름 붙이고
`book/<lang>/` 아래에서 언어별로 해결됩니다.

`#`으로 시작하는 항목은 페이지가 아니라 제목입니다. `##`는 권을 열고 `#`는 그
안의 절을 열며, 라벨은 `languages`와 같은 순서로 언어별 제목 하나씩을
싣습니다. 이 책이 하나의 목차, 하나의 사이드바, 하나의 검색 인덱스 아래에서
핸드북과 레퍼런스 두 권인 방법이 그것입니다. 제목은 라벨이므로 설정 파일에
살고, 챕터 디렉터리에는 독자가 열 수 있는 파일만 남습니다.

## 폴백, 이것이 핵심

mdBook에서 책을 번역한다는 것은 평행한 책 하나를 더 유지한다는 뜻입니다. 아직
번역되지 않은 챕터는 없는 페이지입니다.

Tomo는 각 챕터를 언어별로 해결하고, 없으면 폴백합니다.

```maca
build_chapter(root: str, out: str, title: str, langs: str, lang: str,
              fallback: str, chs: str[], titles: str[], ci: int) -> int {
    ch = chs.get(ci)
    own = root ++ "/book/" ++ lang ++ "/" ++ ch ++ ".md"
    src = file_exists(own)
        ? own
        : root ++ "/book/" ++ fallback ++ "/" ++ ch ++ ".md"
    file_exists(src)
        ? write_chapter(out, title, langs, lang, chs, titles, ci,
                        read_file(src))
        : 0
}
```

번역되지 않은 챕터에 닿은 한국어 독자는 한국어 페이지 위에서 사이드바와 내비게이션이
그대로인 채로 영어 본문을 봅니다. 책이 깨지는 일은 없습니다. 부분적으로 번역된
것일 뿐입니다. 덕분에 번역을 한 챕터부터 시작해서 즉시 쓸모 있게 만들 수
있습니다. 배포하려면 먼저 완성되어야 하는 대신에요. 사실 대부분의 번역이 끝내
일어나지 않는 진짜 이유가 그것입니다.

목차도 섞습니다. 챕터의 제목은 자기 `# 헤딩`에서 오고, 어느 언어로 해결되었든
그것을 씁니다.

## 렌더러

핵심은 순수 함수입니다.

```maca
render(md: str) -> str
```

마크다운이 들어가고 HTML이 나옵니다. IO는 없습니다. 나머지(파일 읽기, 챕터
목록 순회, 사이트 쓰기)가 이것을 감쌉니다. 이 분리가 테스트를 가능하게 합니다.
게이트는 샘플에 `render`를 호출하고 HTML을 검사합니다.

줄들 위의 fold이고, 누산기를 넘깁니다.

```maca
render_lines(lines: str[], i: int, acc: str) -> str =>
    i >= lines.length() ? acc : render_line(lines, i, acc)
```

여러 줄에 걸치는 블록 요소(문단, 인용, 리스트, 표, 코드 펜스)는 자기 끝을
찾아 그 구간을 통째로 소비합니다.

```maca
render_para(lines: str[], i: int, acc: str) -> str {
    stop = para_end(lines, i)
    text = join_range(lines, i, stop)
    render_lines(lines, stop, acc ++ p(class=md_class("p"), inline(esc(text))) ++ "\n")
}
```

이건 들리는 것보다 중요합니다. 첫 버전은 소스 줄마다 `<p>` 하나를 냈고, 그래서
줄바꿈된 `**config mode**`가 `<strong>config</p>`가 되었습니다. 마크업이 문단을
가로질러 쪼개진 것이죠. 인용도 같은 버그가 있어서 세 줄짜리 인용이 세 개의
blockquote가 되었습니다. 둘 다 지금은 게이트의 테스트입니다.

`in_code` 플래그가 없다는 점을 보세요. 예전에는 있었습니다. 코드 펜스를
흘려보냈거든요. 여는 `<pre><code …>` 문자열, 그다음 한 줄씩, 그다음 닫는 문자열.
그러려면 fold의 모든 단계가 "지금 펜스 안인가?"를 들고 다녀야 했고, `<pre>`는
원시 텍스트로밖에 쓸 수 없었습니다. 구간을 먼저 모으면 순회 한 번을 더 하는
대신 마크업을 마크업으로 쓸 수 있습니다.

```maca
render_fence(lines: str[], i: int, acc: str, fence: str) -> str {
    stop = fence_end(lines, i + 1)
    lang = fence.substr(3, fence.length() - 3).trim()
    html = pre(class=md_class("pre"),
               code(class=pre_code_class() ++ lang_class(lang),
                    highlight(lang, fence_body(lines, i + 1, stop))))
    render_lines(lines, stop + 1, acc ++ html ++ "\n")
}
```

## 하이라이팅은 특별 취급이 아니라 훅

`render_fence` 가 부르는 함수는 자기가 아무것도 모르는 함수 하나뿐입니다.

```maca
highlight(lang: str, src: str) -> str
```

펜스의 태그가 들어가고 이스케이프된 HTML이 나옵니다. 답하는 쪽은
`apps/tomo/highlight.maca` 입니다. `maca` 로 태그된 펜스는 `crates/lexer` 를 따르는
스캐너를 얻고, 설정 파일과 셸 언어들은 얕은 범용 스캐너를 얻으며, **하이라이터가
없는 태그는 그냥 이스케이프된 평문으로 떨어집니다**. 이 마지막 경우가 설계의
좋고 나쁨을 가릅니다. 태그 없는 프로그램 출력 블록은 다른 언어를 위해 쓰인
규칙에 망가지지 않고 들어간 그대로 나와야 합니다.

언어를 하나 더하는 일은 함수 하나와 분기 하나이고, 렌더러는 바뀌지 않습니다.

```maca
hl_ini(src: str) -> str => hl_words(src, ";", IniWords)
```

Maca 스캐너가 값을 하는 지점은 정규식이 틀리는 자리들, 곧 이 책이 온통 그것으로
이루어진 자리들입니다. 붙은 `x?` 와 띄어 쓴 `c ? a : b`, 포맷 스펙 `{x:>8}` 와
보간 안의 삼항, `data-tomo` 와 `a - b`. 짐작하는 대신 렉서를 따르고, `{…}` 안의
식은 코드로 스캔합니다. 이 책의 흥미로운 코드 절반이 거기 있기 때문입니다.

## 문자열 이어붙이기가 아니라 마크업

Tomo가 내보내는 모든 요소는 [요소 문법](a11-ui.md)으로 쓰였고, 모든 스타일은
컴파일러가 규칙으로 바꿔 주는 유틸리티 클래스입니다. 템플릿은 없고, 손으로 쓴
CSS는 두 조각입니다. 페이지에 밝은 팔레트와 어두운 팔레트가 둘 다 있다고
브라우저에게 알려 주는 한 줄, 그리고 문법 테마의 열 가지 색. 두 번째를 손으로 쓴
이유는 `text-…` 가 *이름 있는* 색만 받기 때문입니다. `text-[#cf222e]` 는 글자
크기로 읽힙니다. 그리고 이름 있는 팔레트 중 밝은 코드 블록 위에서 읽히는 색은
하나뿐이며, 색 하나는 문법 테마가 아닙니다.

거기까지 가는 데 태그가 값이어야 하는 자리가 셋 있었습니다. 마크다운 렌더러는
소스가 아니라 입력을 보고 태그를 고르기 때문입니다.

```maca
heading(level: str, text: str) -> str =>
    element("h" ++ level, id=slug(text), class=md_class("h" ++ level),
            inline(esc(text))) ++ "\n"

cells(parts: str[], i: int, tag: str) -> str =>   // 헤더는 `th`, 그 아래는 `td`
    element(tag, class=md_class(tag), inline(esc(parts.get(i).trim())))
        ++ cells(parts, i + 1, tag)
```

그리고 `<main>` 에 한 번 더. 이 프로그램도, 모든 프로그램이 그렇듯, `main` 을
정의하므로 어떤 호출로도 그 태그에 이름을 붙일 수 없습니다.

이건 단정함을 넘어서는 이유가 있습니다. 컴파일러는 눈에 보이는 `class=`
문자열을 모아서 어떤 CSS 규칙을 만들지 정하는데, 원시 `"""…"""` 문자열 안은
보지 못합니다. 검색 상자가 원시 블록 하나였던 동안, 거기 적힌 모든 클래스는
규칙을 하나도 만들지 못했고, 검색 필드는 아무것도 실패하지 않은 채 스타일 없이
놓여 있었습니다.

## 서버 없는 검색

모든 페이지가 검색 상자를 가집니다. 인덱스는 언어별로, 헤딩당 하나씩 생성되고
그 절의 텍스트를 소문자로 담습니다.

```javascript
window.TOMO_INDEX=[{"u":"08-collections.html#lists","c":"Collections",
                    "s":"Lists","x":"a list of t is written…"},…]
```

페이지가 fetch하는 JSON이 아니라 페이지가 로드하는 `<script>`로 나갑니다. 게으름이
아닙니다. `file://`로 디스크에서 바로 연 책은 `fetch`를 할 수 없습니다. mdBook의
검색은 웹 서버가 필요하고, 이것은 USB 스틱의 폴더에서도 동작합니다.

## 랜딩 페이지

책은 어떤 것을 설명합니다. 아무것도 모르고 도착한 사람에게는 목차보다 먼저 그
"어떤 것"이 무엇인지가 필요하죠. 그래서 언어별로 하나씩 있는 `home.md`를 같은
렌더러가 렌더링해 `/index.html`과 `<lang>/home.html`이 됩니다.

베껴갈 만한 점이 둘 있습니다. 버튼 세 개는 Markdown이 아니라 레이아웃에
있습니다. 루트 랜딩과 언어별 랜딩은 깊이만 다른 같은 Markdown이라, 거기 쓴
사이트 상대 링크는 둘 중 하나에서만 맞을 수 있으니까요. 그리고 페이지는 첫
`##`에서 갈립니다. 그 위가 홍보 문구이고, 버튼이 그다음에 오고, 논증이 이어
집니다. 읽는 사람이 두 화면 분량의 산문 뒤가 아니라 그 전에 나갈 문을 얻도록요.

`home.md`가 없는 책도 루트 페이지를 받습니다. 예전의 그 언어 선택 화면이죠.
랜딩 페이지는 직접 써서 선택하는 것입니다.

## 빌드하기

```
maca run apps/tomo/tomo.maca
```

모든 언어의 모든 챕터를 렌더하고, 언어별 목차와 검색 인덱스를 쓰고, 페이지를
몇 개 썼는지 보고합니다. 테스트 스위트가 실제 핸드북을 빌드하고 결과를
검사합니다. 번역되지 않은 챕터가 폴백하면서도 한국어 페이지로 나오는지까지요.


## 이 책이 스스로 지키는 두 가지

**순서는 한 곳에만 있습니다.** 예전에는 `<lang>/index.html`이 목차 전체를 본문에
그리고, 그 옆에서 사이드바가 같은 목차를 또 그렸습니다. 독자는 목차를 두 개
만나고 둘이 다른지부터 따져야 했습니다. 순서는 사이드바가 들고, 그 옆 페이지는
각 권이 무엇을 위한 것이고 어디서 시작하는지만 말합니다. `sitegen.maca`가 그
페이지의 챕터 링크 수를 세서 권당 하나가 아니면 실패합니다.

**챕터는 소제목이 아니라 문장으로 엽니다.** `## 함수는 값이다`에 떨어지면 그
절이 무엇에 관한지는 알지만, 이 챕터가 무엇을 위한 것인지, 내가 제대로 찾아온
것인지는 알 수 없습니다. 제목 바로 아래 첫 줄이 이 페이지가 답하는 것을
말합니다. 이것도 두 언어 모두에서 검사합니다. 아무도 검사하지 않는 관습은 다음
기여자까지만 유지되기 때문입니다.

## 이 책에서 무엇을 쓰는가

줄 위를 걷는 모든 순회에 누산기를 든 재귀. 모든 파싱에 `str` 메서드. 챕터와 언어
집합에 리스트. 읽고 쓰는 데 파일 IO. 출력의 모든 바이트에 요소 문법과 생성된
스타일. 원시 `"""…"""` 문자열은 딱 하나에만: 검색을 굴리고 사이드바를 접는
JavaScript에. 원시 블록은 그러라고 있는 것이니까요. 마크업을 위장한 것이 아니라
다른 언어를 담으라고요.

공교롭게도 합타입은 안 씁니다. 렌더러가 토큰 타입이 아니라 줄 접두사로
분기하기 때문입니다. 더 큰 마크다운 구현이라면 합타입을 원할 것입니다.

천 줄쯤 됩니다. 그것이 정적 사이트 생성기 전부입니다. 자기가 문서화하는 언어로
쓰인 채로요.
