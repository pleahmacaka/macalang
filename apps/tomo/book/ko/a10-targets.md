# 타깃

같은 소스가 아주 다른 것들로 컴파일됩니다. 어느 쪽이 나오는지는 플래그가
정하지, 방언이 정하지 않습니다. `#ifdef`도, 타깃별로 잘려나간 언어도, 별도의
표준 라이브러리도 없습니다. Maca를 쓰고, 어디에 떨어질지 고르면 됩니다.

둘러보기는 [프로그램이 도착하는 곳](15-targets.md)입니다. 이 장은 모든 타깃,
모든 플래그, 그리고 각 타깃이 거부하는 것의 정확한 목록입니다.

## 플래그

| 명령 | 만드는 것 |
|---|---|
| `maca build app.maca -o app` | C를 거친 정적 네이티브 바이너리 |
| `maca build app.maca --target js -o out` | 자체 완결적인 페이지 |
| `maca build app.maca --target jvm --cp …` | Java 소스 |
| `maca build app.maca --target rust` | Rust 소스 |
| `maca build app.maca --target embedded --mcu cortex-m0` | freestanding C |
| `maca build app.maca --target nix` | `.nix` 식 |
| `maca build app.maca --target tauri` | 데스크톱 애플리케이션 스캐폴드 |

`--mcu`는 `embedded`의, `--cp`는 `jvm`의 것입니다. `--target`이 없으면 네이티브
바이너리가 나옵니다.

## 네이티브, C를 거쳐

`--target` 없이 쓰면 Maca는 C를 거쳐 컴파일하고 정적 바이너리를 링크합니다.
나머지 전부가 여기에 견주어 측정되는 기준입니다. 배포할 런타임도, 시작할
인터프리터도, 멈출 수집기도 없습니다. 생성된 C는 시스템에 있는 컴파일러로
넘어가므로, 여러분이 얻는 최적화기는 30년치 작업이 쌓인 그것입니다.

```
maca build app.maca -o app
./app
```

수치 연산이 몰린 구간은 벡터화를 위해 LLVM으로 내려갈 수 있습니다. 이 경로는
SIMD에만 존재하고 나머지와는 C ABI로 링크되므로, 프로그램 전체가 아니라
국소적인 결정으로 남습니다.

## JavaScript

```
maca build app.maca --target js -o out
```

는 자체 완결적인 페이지 하나를 만듭니다. JavaScript 백엔드는 Maca의 반응형 UI
문법을 이해하고, 찾아낸 Tailwind 유틸리티 클래스에 대한 CSS를 생성합니다.
그래서 Maca로 쓴 인터페이스에는 번들러도, `package.json`도, 저 명령 외의 빌드
단계도 필요 없습니다. 이 책과 함께 나가는 플레이그라운드가 정확히 이렇게
컴파일된 `.maca` 파일 하나입니다.

같은 문법이 네이티브 타깃에서도 동작합니다. 거기서는 요소가 DOM 노드가 아니라
HTML 문자열로 렌더링되는데, 정적 사이트 생성기에 필요한 것이 바로 그것이고
[UI 문법](a11-ui.md)의 주제입니다.

## JVM과 Rust

이 둘은 배포보다 *도달 범위*에 관한 것입니다. Maca가 어떤 생태계를 다시
구현하는 대신 그냥 쓸 수 있게 하려고 존재합니다.

`--target jvm`은 Java 소스를 내보내고, 그래서 JVM 연동이 평범한 일이 됩니다.
저장소의 예제는 Fabric을 통한 Minecraft 모드입니다. `--target rust`는 Rust
소스를 내보내고 `maca.toml`의 `[rust-dependencies]`에서 의존성을 가져오므로,
crates.io 라이브러리가 설정 한 줄 거리에 있습니다.

대가는 그 타깃의 시작 비용과 런타임을 함께 물려받는다는 것입니다. 필요한
라이브러리가 그쪽에 있으면 이것들을, 아니면 네이티브를 고르세요.

## 임베디드

```
maca build blink.maca --target embedded --mcu cortex-m0
```

는 베어메탈 마이크로컨트롤러용 freestanding C를 내보냅니다. libc도, 할당기도,
운영체제도 없습니다. Cortex-M과 RISC-V를 지원합니다. 메모리 맵 레지스터는
평범한 Maca 값이고, 필드 쓰기는 알맞은 폭의 read-modify-write로 낮춰집니다.

"freestanding"에서 두 가지가 따라 나오고, 컴파일러가 그것을 직접 말해 줍니다.
쓰지도 않은 파일에 대해 C 툴체인이 불평하게 두지 않고요. 콘솔이 없으므로
`info`와 그 형제들은 쓸 수 없습니다 — UART를 `mmio_write`로 직접 다루세요.
그리고 `main`은 아무것도 반환하지 않습니다. 종료 코드를 건네줄 프로세스가
없으니까요. 리셋 핸들러가 호출하고, 반환하면 멈춥니다.

여기서 `int`는 64비트가 아니라 32비트 워드입니다. MMIO 어휘는
`mmio_write`/`mmio_read`, `set_bits`/`clear_bits`/`toggle_bits`, `bit`,
`shl`/`shr`/`bit_or`/`bit_and`, `delay`, `nop`이고, `for _ in forever()`가
슈퍼 루프입니다.

C를 거쳐 컴파일하는 것을 가장 잘 정당화해 주는 타깃입니다. 특정 칩의 C
툴체인은 이미 존재하고, Maca는 마이크로컨트롤러 계열마다 코드 생성기를 들고
다니는 대신 그것을 씁니다.

## Nix

`--target nix`는 [설정 모드](a12-config.md)의 출력입니다. 이 목록에 들어가는
이유는 Maca를 특이하게 만드는 타깃이기 때문입니다. 바이너리를 만들어낸 그
언어가 그 바이너리가 돌아갈 머신도 기술할 수 있고, 양쪽 다 배포되기 전에 타입
검사를 받습니다.

## Tauri

`--target tauri`는 데스크톱 애플리케이션을 스캐폴딩합니다. 인터페이스는
JavaScript 백엔드로, 그 아래는 네이티브 바이너리로요.

## 각 타깃이 거부하는 것

타깃은 지킬 수 없는 것을 컴파일 시점에, 이름을 대며 거부합니다. 그러지 않으면
쓰지도 않은 생성 코드에 대한 에러를 보게 됩니다.

| 타깃 | 거부하는 것 |
|---|---|
| native | `on:click=`와 그 형제들 — 문자열에는 이벤트 핸들러가 붙을 자리가 없음 |
| `rust` | 본문 없는(FFI) 함수, `import c`/`import py`, 선언되지 않은 크레이트를 가리키는 `import rust`, 반환하거나 저장하는 빌린 외부 파라미터 |
| `embedded` | `info`와 나머지 콘솔 빌트인, 반환 타입이 있는 `main` |
| `nix` | 비어 있지 않은 이펙트 행 전부 — [이펙트와 async](a7-effects.md) 참조 |

## ABI와 링크

네이티브 쪽은 전부 **C ABI**로 모입니다. C 백엔드와 LLVM SIMD 구간이 내보내는
오브젝트는 서로 링크되고, FFI 선언은 평범한 extern이며, async 함수는 평범한
함수입니다. `spawn`/`await`는 본문이 하는 일을 바꿀 뿐 호출 방법을 바꾸지
않습니다.

하이브리드 네이티브 경로가 국소적인 결정으로 남는 이유가 이 성질입니다. 호출
방법에 양쪽이 합의하므로, SIMD 구간은 나머지 프로그램이 모르는 채로 LLVM을 거쳐
내려갈 수 있습니다.

## 무엇을 고를까

대부분의 프로그램은 네이티브를 원하고, 질문은 프로그램 바깥의 무언가가 답을
정할 때만 생깁니다. 브라우저, 마이크로컨트롤러, Java API, 포팅에 한 달 걸릴
크레이트 같은 것들이요. 쓸모 있는 성질은 Maca에 백엔드가 많다는 게 아니라,
그 사이를 옮겨 다니는 비용이 다시 쓰기가 아니라 플래그 하나라는 점입니다.

## 목록이 멈추는 지점

여기 있는 타깃은 전부 무언가에 닿는 것으로 제 자리를 법니다. 브라우저,
마이크로컨트롤러, JVM의 라이브러리, crates.io. 규칙은 그게 전부이고, 목록이 이
길이인 이유도 그것입니다.

사람들이 묻는 것은 BEAM 타깃입니다. Maca의 동시성 모델이 어울려 보이니까요.
목록에 없는 이유는, 그것이 도달 범위가 아니라 우아함 때문에 추가되는 첫 백엔드가
될 것이기 때문입니다. [컬러블라인드 async](a7-effects.md)는 이미 C 런타임의
pthread 위에서 돌아가고, Erlang 식 낮추기는 잘 돌아가는 것을 두 번째로, 진짜
다르게 구현하는 일입니다. 도달 범위는 이유가 됩니다. 대칭은 아닙니다.
