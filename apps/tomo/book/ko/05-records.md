# 레코드

레코드는 이름 붙은 필드들을 하나의 타입 이름 아래 묶습니다. Maca의 구조체이고,
이 언어의 일꾼입니다.

## 선언과 생성

```maca
Point = {
    x: int
    y: int
}
```

선언은 `Name = { … }`로 읽습니다. 값을 바인딩하는 `=`와 같은 기호인데, 최상위
타입 선언도 바인딩이기 때문입니다. 안에는 한 줄에 `field: type` 하나씩 씁니다.
줄 끝에 쉼표는 필요 없지만 써도 됩니다.

값을 만들 때는 `:`가 아니라 `=`를 씁니다.

```maca
p = Point { x = 3, y = 4 }
```

Maca에서 가장 쓸모 있는 문장부호 규칙입니다. **`:`는 그것이 무엇인지를 말하고,
`=`는 그것이 무엇을 담는지를 말합니다.** 레코드 선언, 레코드 리터럴, 함수
매개변수, 바인딩 모두에서 일관됩니다.

필드는 점으로 읽습니다.

```maca
info("{p.x}, {p.y}")
```

## 갱신

레코드는 값입니다. 바뀐 것을 얻으려면 `with`를 씁니다.

```maca
q = p with { y = 5 }
```

`q`는 `x = 3, y = 5`인 `Point`이고, `p`는 그대로입니다. 여러 필드를 한 번에
바꿀 수 있고, 언급하지 않은 필드는 그대로 넘어옵니다.

```maca
r = p with { x = 0, y = 0 }
```

이것이 반드시 복사인 것은 아닙니다. 4장이 이유를 설명합니다. 아무도 `p`를 붙들고
있지 않을 때, 컴파일러는 `with`를 이미 있던 메모리에 대한 저장으로 만들 수
있습니다. 함수형 버전을 쓰고 명령형의 성능을 얻는 것, 그것이 설계 전체입니다.

만들어 나가는 중인 지역 레코드를 위한 직접 필드 대입도 있습니다.

```maca
p.x = 10
```

## 시그니처 속의 레코드

레코드 타입은 다른 타입과 똑같이 쓰입니다.

```maca
Rect = {
    w: int
    h: int
}

area(r: Rect) -> int =>
    r.w * r.h

scale(r: Rect, k: int) -> Rect =>
    r with { w = r.w * k, h = r.h * k }
```

그리고 UFCS — `x.f(y)`는 `f(x, y)` — 덕분에, 메서드로 선언한 적이 없는데도 호출
지점에서는 메서드처럼 읽힙니다.

```maca
big = Rect { w = 2, h = 3 }.scale(10)
info("area: {big.area()}")
```

`impl` 블록도 `self`도 없고, "메서드"와 "첫 인자가 Rect인 함수" 사이의 구분도
없습니다. 자유 함수 하나면 충분합니다.

## 레코드를 담은 레코드

필드는 어떤 타입이든 될 수 있습니다. 다른 레코드나 그 리스트도 됩니다.

```maca
Line = {
    from: Point
    to: Point
}

Shape = {
    name: str
    points: Point[]
}
```

접근은 뻔한 방식으로 중첩됩니다. `l.from.x`.

레코드는 **자기 자신**을 참조할 수도 있습니다. 트리를 만드는 방법입니다.

```maca
Node = {
    label: str
    children: Node[]
}
```

동작하고, 왜 컴파일러의 도움이 필요한지 알아둘 가치가 있습니다. C에서 자기 자신의
배열을 담은 구조체는 정의 순환입니다. 배열 타입은 구조체의 크기를 필요로 하고,
구조체는 배열을 필요로 하니까요. Maca의 C 백엔드는 레코드 본문 앞에 배열 구조체를
전방 선언하고 연산은 뒤에 내보내어 순환을 끊습니다. 이 과정은 전혀 보이지
않습니다. 자기 참조 레코드가 우연이 아니라 지원되는 기능이라는 뜻이라서
언급합니다.

## 항상 타입 이름을 붙이세요

앞에 타입 이름이 없는 레코드 리터럴 — `{ host = "x", port = 80 }` — 은 파서와
타입 검사기가 받아들이고, 존재하는 필드로부터 구조적 타입을 추론합니다. 하지만
네이티브 백엔드는 이를 지원하지 **않고** 프로그램을 거부합니다.

```
expression not supported by the native backend: Record(…)
```

그러니 실제로는 만드는 모든 레코드에 선언된 타입이 붙습니다. 어차피 그게 옳은
습관입니다. 진단 메시지가 이야기할 수 있는 것은 이름이고, 그 모양은 거의 항상
한 번 이상 등장하니까요.

## 레코드 대 합타입

레코드는 "이것들 전부 동시에"를 말합니다. "이것들 중 하나"가 필요하다면 그것은
합타입이고, 다음 장의 내용입니다.
