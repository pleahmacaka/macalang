# 타입 시스템

검사기가 하는 일을, 정확하게. Maca는 정적 타입이고 대부분 추론됩니다. 함수
경계에만 표기하면 안쪽은 따라옵니다.

가르치는 쪽은 [Maca 배우기](03-common-concepts.md) 곳곳에 흩어져 있습니다.
이 장은 규칙입니다.

## 경계에서의 추론

함수 시그니처가 계약입니다.

```maca
double(n: int) -> int =>
    n * 2
```

지역 변수에는 절대 표기하지 않습니다.

```maca
half(n: int) -> int {
    m = n / 2      // m은 int, 선언할 것 없음
    m
}
```

반환 타입은 생략할 수 있고, 그러면 본문에서 추론됩니다.

```maca
inc(x) => x + 1
```

여기서는 매개변수와 결과가 둘 다 추론됩니다. 그래도 쓰는 편이 낫습니다.
시그니처는 컴파일러가 검사해 주는 문서이고, 반대할 대상이 있을 때 에러 메시지가
훨씬 좋아집니다.

추론이 붙잡을 것이 없는 자리에는 지역 변수도 표기를 답니다. 빈 맵은 무언가
들어가기 전까지 값 타입이 없습니다.

```maca
counts: Map str int = map()
```

## 꺾쇠 없는 제네릭

타입 자리의 **소문자** 이름은 타입 변수입니다.

```maca
identity(x: a) -> a =>
    x

pair_first(xs: a[], fallback: a) -> a =>
    xs.length() > 0 ? xs.first() : fallback
```

여기서 `a`는 "a라는 이름의 타입"이 아니라 "아무 타입, 세 자리 모두 같은 것"
입니다. 선언할 `<T>`가 없습니다. 소문자가 이미 변수를 뜻하고 대문자가 이미 구체
타입을 뜻하기 때문입니다.

함수 시그니처는 스킴으로 일반화되고 호출마다 새로 인스턴스화되므로,
`identity(1)`과 `identity("x")`가 둘 다 되고 서로를 제약하지 않습니다. 표준적인
Hindley–Milner 추론입니다.

C 백엔드는 **단형화**합니다. 서로 다른 인스턴스화마다 생성된 C 안에 특수화된
함수가 하나씩 생깁니다. 런타임 박싱도 디스패치도 없습니다. 제네릭 함수는 손으로
쓴 특수화 버전과 정확히 같은 비용이 듭니다.

## 점진적 타이핑과 `any`

모든 것을 알 수는 없습니다. 외부 함수, 표준 라이브러리의 일부 구석, 백엔드
경계를 넘는 값에는 줄 수 있는 Maca 타입이 없습니다. 그런 것들을 위해 `any`가
있고, 모든 것과 통일됩니다.

Maca를 *점진적* 타입이라 부르는 이유입니다. 엄격한 코어는 진짜 추론을 하고,
`any`는 가운데 뚫린 구멍이 아니라 가장자리의 탈출구입니다. 실제로는, 미지의
영역으로 들어가는 호출이 가짜 에러의 폭포를 만들지 않는다는 뜻입니다. 동시에
그 영역의 실수는 잡히지 않는다는 뜻이기도 합니다.

메서드 호출이 그런 곳 중 하나이고, 예외를 알아 둘 값이 있습니다. `str`와
`T[]`의 메서드 집합은 **닫혀 있으므로**, 거기에 없는 이름은 오타이고 링커까지
살아남는 대신 제안과 함께 보고됩니다. `any` 수신자는 점진적으로 남습니다. 외부
코드에 닿는 방법이 그것이기 때문입니다. 닫힌 두 집합은
[표준 라이브러리](a3-stdlib.md)에 있고, 테스트가 그 안의 모든 이름을 컴파일해
실행합니다.

## 이펙트

함수의 타입은 인자와 결과만이 아닙니다. 검사기는 함수가 무엇을 *하는지* —
그 **이펙트** — 도 추적하며, 이펙트는 추론될 뿐 선언되지 않습니다.
[이펙트와 async](a7-effects.md)가 전체 설명입니다. 다섯 개의 행, 각각을
도입하는 것, 그리고 각각이 어디서 강제되는지.

## 진단 메시지

여섯 종류이고, 각각 한 가지를 정확히 뜻합니다.

| 진단 | 의미 |
|---|---|
| `TypeMismatch` | 같아야 할 두 타입이 같지 않음 |
| `NonExhaustive` | `match`가 모든 변형을 다루지 않음 |
| `Immutable` | 상수에 대한 대입 |
| `UndefinedName` | 어디에도 정의되지 않은 이름 호출 |
| `UnknownOption` | 존재하지 않는 설정 옵션 |
| `EffectInConfig` | config 모드의 순수하지 않은 연산 |

`TypeMismatch`는 이름에서 느껴지는 것보다 넓습니다. 호출 인자 개수도
불일치입니다.

```
TypeMismatch: call to `f` expects 2 argument(s), got 3
```

`if`나 삼항의 갈래가 서로 다른 것도요. 꽤 흔한 실수입니다.

```maca
x = c ? 1 : "two"
// TypeMismatch: ternary branches disagree: expected int, found str
```

여섯 가지가 낼 수 있는 모든 메시지와 각각에 대한 대처법은
[진단 메시지](a4-diagnostics.md)에 있습니다.

## 상수

바인딩은 기본적으로 가변입니다.

```maca
count = 0
count = count + 1
```

셋 중 하나가 상수로 만듭니다. `const`, 뒤에 붙는 `as const`, 그리고 대문자로
시작하는 이름입니다.

```maca
const Limit = 100
step = 5 as const
Origin = 0
```

어느 것이든 재대입하면 컴파일 에러입니다.

```
Immutable: cannot reassign constant `Limit` — declare it mutable with
`Limit = …` (no `const`)
```

대문자 규칙은 사람들이 이미 상수를 그렇게 쓰기 때문에 있지만 암묵적이라서,
`maca lint`가 의도한 곳에는 `const`를 명시하도록 권합니다.

## 에러 읽기

타입 에러는 함수와 위치를 알려줍니다.

```
TypeMismatch: in call to `d` (argument 2): type mismatch: expected P, found int
```

메시지가 구체 타입이 아니라 타입 변수에 관한 것이라면, 보통 위쪽 어딘가에
표기가 빠진 것이 원인입니다. 검사기가 의도한 것보다 일반적인 타입을 추론한
것이죠. 머릿속에 있던 시그니처를 적어 주면 해결되거나, 당신의 모델과 코드가
어디서 어긋나는지 정확히 알려 줄 것입니다.
