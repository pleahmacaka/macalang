# 셀프호스팅 컴파일러

Maca는 부트스트랩 중이고, 이 장은 그 모양입니다.

## 두 단계

**스테이지 0**은 `crates/` 아래의 Rust 컴파일러입니다. 동결되어 있고, 진짜
부트스트랩 버그 때문에만 바뀝니다.

**스테이지 1**은 `modules/maca/` 아래의 Maca 컴파일러입니다. 새 컴파일러 작업이
속하는 곳입니다. 스테이지 0이 이것을 컴파일하고, 테스트
게이트(`crates/driver/tests/selfhost.rs`)가 계속 동작하는지 확인합니다.

Rust 크레이트를 키우는 것보다 `modules/maca/*.maca`에 추가하는 쪽을 택하세요.

## 스테이지 1이 지금 하는 일

프론트엔드 전체가 네이티브로 돕니다.

```
lexer.maca → parser.maca → ast.maca → check.maca → emit_c.maca
                                                 → emit_rust.maca
```

손으로 쓴 렉서, 재귀 `Expr` AST와 pretty-printer를 만드는 재귀 하향 파서, 타입
검사기, 그리고 C와 Rust를 각각 내보내는 백엔드 **둘**.

다루는 범위는 원시 식 언어 전체, 문자열 보간, 선언된 타입이 C의
`const char*`/`double`/`bool`과 Rust의 `String`/`f64`로 흘러가는 타입 배선된
시그니처, 필드 접근이 되는 레코드, 그리고 바인딩 패턴이 붙은 `match`와 함께
무인자와 페이로드 합타입 모두입니다.

검사기는 모듈의 함수 시그니처, 레코드 필드, 합타입 변형, 지역 이름들을 담은
환경을 들고 다녀서 호출의 결과 타입, 인자 개수, 레코드에 없는 필드, 선언한
반환 타입과 어긋나는 본문을 답할 수 있습니다.

## 게이트가 동작하는 방식

이 테스트는 출력이 *기대한 대로*인지가 아니라 **동작하는지**를 확인합니다.

1. 스테이지 0이 호스트 `cc`로 스테이지 1 컴파일러를 네이티브 바이너리로 빌드합니다.
2. 그 바이너리가 Maca 프로그램 하나를 두 번 처리합니다. 한 번은 C를, 한 번은
   Rust를 내보내면서요.
3. 내보낸 C를 `cc`로, 내보낸 Rust를 `rustc`로 컴파일해 실행합니다.
4. 둘 다 `self-hosted!`를 출력하고 `42`로 종료해야 합니다.

"C 경로는 되는데 Rust 경로가 조용히 안 되는" 종류의 버그를 통째로 잡습니다.

## 이것을 가능하게 한 두 기능

**문자열 스캐닝.** `chars`, `length`, `at`, `get`, `slice`, 그리고 문자 분류
`is_whitespace`, `is_ascii_digit`, `is_alpha`. `modules/maca/lexer.maca`가 쓰는
어휘의 전부입니다.

**재귀 레코드 타입.** AST 노드가 AST 노드의 리스트를 담습니다.

```maca
Expr = {
    kind: int
    text: str
    children: Expr[]
}
```

C에서 이것은 정의 순환입니다. 백엔드는 레코드 본문 앞에 배열 구조체를 전방
선언하고 연산은 뒤에 내보내어 순환을 끊습니다
([메모리와 소유권](a8-memory.md)).

## 소스 읽기

`apps/maca1/main.maca`가 진입점이고 테스트 스위트 역할도 겸합니다. 일련의
프로그램을 렉싱, 파싱, 검사, 코드 생성하고 각각을 보고합니다.

```
maca run apps/maca1/main.maca
```

`lexer.maca`는 문자 스캐너, `parser.maca`는 우선순위 표가 붙은 재귀 하향,
`emit_c.maca`는 문자열 템플릿입니다.

## 두 스테이지가 갈리는 지점

스테이지 1은 부분집합을 컴파일합니다. 클로저, 제네릭, 이펙트 행, 모듈 시스템은
스테이지 0에만 있으므로, 그것을 쓰는 프로그램은 Rust 컴파일러를 통과합니다.

스테이지 0은 스테이지 1을 컴파일하는 데 필요한 만큼에서 얼어 있고, 스테이지 1은
게이트가 걸린 증분 하나씩 자랍니다.
